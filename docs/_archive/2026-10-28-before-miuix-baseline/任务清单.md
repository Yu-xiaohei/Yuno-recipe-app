# 「于の食谱」实施任务 v3

> 2026-10-28。AI Agent承担设计、开发、自动测试与交付；用户在必要的风格、真机体验、授权与发布节点参与。以下均为待实施任务，不沿用旧清单的“两Tab/固定三餐/全部指标同阈值”等规则。

## M0 · 数据与契约

- [ ] T0.1 将样例整理为同一套可追溯演示数据，核对名称、不含主食、单位、生熟状态和来源。
- [ ] T0.2 为Recipe/GoalProfile/MealRecord/导入包建立版本化schema和校验器。
- [ ] T0.3 实现无副作用校验及迁移预览；保留原数据与diff。
- [ ] T0.4 调整改造技能并生成一份可核验新样例；不编造缺失权重。
- [ ] T0.5 编写合计、缺失值、精度、口径及高版本拒绝测试。

验收：可追溯数据、机器校验报告、错误样例明确失败。原始数据未被静默覆盖。

## M1 · 核心本地闭环

- [ ] T1.1 核实Android/Compose/候选库/构建工具版本与最低系统；建立可编译工程。
- [ ] T1.2 三Tab，默认食谱；本地数据优先进入，不等待联网。
- [ ] T1.3 食谱列表、详情、至少2字符搜索、中文/拼音、筛选、多选逻辑、历史搜索。
- [ ] T1.4 日期和自定义餐次、添加食谱/独立食材、新建/编辑/保存/详情。
- [ ] T1.5 本地事务、草稿恢复、锁定与解锁、删除确认及历史快照。

验收：断网完成浏览→搜索→加入配餐→保存→重启查看。无餐日期可进入。更新公共食谱不改变历史数据。

## M2 · 营养目标与调配

- [ ] T2.1 日目标、餐次比例、手动覆盖、区间/指定值/仅上限、未配置状态。
- [ ] T2.2 实现有界权重求解，提供±100g、直接输入、重置与食材预览。
- [ ] T2.3 测试锁定、边界、不可达、零能量、缺失能量、反复调整不累积漂移。
- [ ] T2.4 校验未舍入与量化后残差；展示实际结果与偏差。
- [ ] T2.5 目标快照、餐次模板停用/重命名、历史不追溯重算。

验收：可达时满足目标及边界；不可达时不宣称成功；钠低于仅上限不显示缺少；目标0不除零；缺失目标不标红。

## M3 · 导入、更新与个人同步

- [ ] T3.1 食谱与配餐JSON预览导入、重复ID/冲突处理、事务回滚、导出往返。
- [ ] T3.2 公共双源、相对路径、hash/revision、校验后提交、逐条失败重试。
- [ ] T3.3 保留旧数据刷新、离线提示、应用更新下载与完整性/签名兼容检查。
- [ ] T3.4 WebDAV配置、安全凭据、测试连接、队列、条件写入、同步状态。
- [ ] T3.5 双端冲突副本、删除tombstone、解决冲突；不支持条件写入时降级备份。
- [ ] T3.6 故障注入：401/403/404、断网、超时、并发改同一记录、远端损坏、删除后另一端上线。

验收：往返导入数据一致；取消无写入；部分食谱失败不假报完整更新；同步不丢双方修改；日志与导出不含凭据。

## M4 · 设计补齐与体验

- [ ] T4.1 统一Figma演示数据、目标类型、营养单位、锁定及同步文案。
- [ ] T4.2 补添加选择页、目标编辑器、导入预览、冲突处理及空/错误/深色状态。
- [ ] T4.3 配餐编辑实际/目标/状态列头及固定保存区，手机食材可展开明细。
- [ ] T4.4 检查现有组件家族、自动布局、可见文案与原型连接。
- [ ] T4.5 玻璃小原型及真机验证后实现导航、共享过场、微动效与降级。
- [ ] T4.6 验证字体放大、深色、减弱动画、键盘、三键/手势导航及性能。

验收：提供代表页面截图、原型流程证据及真机限制。静态玻璃截图不冒充运行效果。
