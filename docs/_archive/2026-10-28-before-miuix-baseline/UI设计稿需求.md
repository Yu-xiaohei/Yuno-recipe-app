# 「于の食谱」UI 设计交接 v3

> 2026-10-28。以现有 Figma 为视觉基础，产品规则见《完整方案 v3》和《UX v3》。保留已建组件，优先调整内容与状态。未在 Figma 实现的要求不能据此标为已完成。

## 1. 基础规范

- 页面参考宽 430，采用自适应布局，不将参考像素机械等同所有 Android 设备的 dp。
- 主强调 #3482FF，浅底 #F7F7F8，白色卡片；深色由语义变量映射。品牌图标保留现有橙色。
- 保留碗叶占位、胶囊导航和筛选、连续圆角。玻璃仅用于悬浮操作与必要表面；正文对比和信息层级优先。
- 文字采用现有字体家族，字号、颜色与间距归入变量。辅助信息不得仅靠低透明度区分。
- 状态色表示判断结果，不固定代表蛋白/脂肪/碳水。同时提供文字或图标。
- 图片 16:9 详情、方形卡片缩略；缺失时统一占位。

## 2. 页面与关键状态

| 页面 | 关键内容 | 必须补齐的状态/行为 |
|---|---|---|
| 启动 | 品牌、进度 | 本地数据直接进入；无数据才阻塞显示错误与重试 |
| 食谱首页 | 图片、名称、热量、重量、2–3 标签 | 默认/有旧数据同步/首次加载/离线/筛选空 |
| 搜索 | 输入、关闭、最近搜索、结果 | 至少2字符、空输入、组合输入、不足、无结果、清除确认 |
| 筛选菜单 | 重量/热量/分类多选 | 全部、已选、清空；同类 OR、跨类 AND |
| 食谱详情 | 图、范围提示、营养、食材、来源 | 不含主食提示、无图、营养缺失、展开、来源链接 |
| 今日配餐 | 全天合计、餐次卡、营养入口 | 有餐/无餐、未设目标、自定义餐数 |
| 日历与日期详情 | 选择日期、查询、当日餐次 | 无餐也可点、今日、选中、有餐、跨月 |
| 配餐详情 | 组合食谱、食材快照、更多 | 历史快照、锁定/解锁、同步状态、删除确认 |
| 新建/编辑配餐 | 日期餐次只读、实际/目标/状态、食谱调整 | 空、已改、不可达、锁定、保存失败、待同步 |
| 添加食谱/食材 | 两类选择、搜索、多选、重量口径 | 已选数、缺营养、自定义食材、返回保留草稿 |
| 营养目标 | 日/单餐、分配比例、目标类型 | 未设置、手动覆盖、差额、区间无效、餐次停用 |
| 设置 | 食谱数据、目标、备份、通用、关于 | 数据源分别表示食谱和应用更新源 |
| WebDAV | 配置、测试、频率、状态 | 未配置、测试中、失败、离线队列、冲突处理 |
| 导入导出 | 文件选择、预览、重复项、确认 | 无效/不兼容/取消/成功/部分拒绝说明 |
| 开发者模式 | 源诊断、日志、校验 | 正式默认隐藏；10次点击版本号解锁；脱敏 |
| 应用更新 | 版本、说明、下载、安装入口 | 稍后、取消、失败、校验失败、安装器返回 |

## 3. 重点修改

### 配餐编辑

显示清晰列头“实际 / 目标 / 状态”，以同一份样例数据联动各区域。条目重量、热量与顶部合计必须一致；不能把静态占位数字当成计算结果。

每道食谱滑块默认 ±100g，并提供输入与重置。旁边标明“按调配优先级调整食材”；可展开看原克数→新克数。锁定食材标识“不参与调整”。不可达目标显示可达范围与实际值。

“允许编辑”改为“锁定配餐”，说明“锁定后可解锁再编辑”。“同步至云端”在未配置时给配置入口。底部保存按钮保持可见，避开键盘和手势区；长页面使用固定操作区，不依赖滚到末尾寻找。

### 营养目标

“营养配比/总目标比例”改为“餐次分配比例”，防止与三大营养供能比混淆。指标编辑器包含目标类型：指定值、目标区间、仅上限。未设目标显示“未设置”。

膳食纤维统一 g；钠、维生素 C 为 mg；维生素列明确为维生素 C。公共发布稿的目标样例标为示例，不提供假定适合所有用户的默认数值。

### 食谱详情

标题与内容范围一致，例如已去面条的食谱显示“西红柿鸡蛋面卤”，提示不含面条。温馨提示使用当前营养数据，不复用旧菜或旧版本数字。

食材默认按行展开，完整表格为可选详细视图。无需为了展示全部字段把九列表格缩到手机屏宽。来源、生成信息、许可放在次级区块。

### 同步与恢复

移除无提示“最新覆盖旧文件”的语义。冲突页同时显示设备、修改时间和内容差异，提供保留本机、保留远端、两份都保留；处理前双方数据均在。

清缓存与清本地数据明确分开。清数据确认页列出配餐、导入食谱及同步状态，支持先导出；正文不展示密码和 token。

## 4. 组件维护

当前组件库已有按钮、搜索/输入、筛选、导航、食谱/餐次卡、设置行、日历、弹窗、菜单及业务模块。修改时优先更新同一家族，避免实例与母组件语义不一致。

新增重点：目标类型编辑器、实际/目标/状态行、调配不可达提示、锁定状态、同步状态、冲突对比、导入预览。命名保持简洁；可见文案不塞实现细节。

每个可操作组件至少覆盖默认、按压、禁用、加载、错误；页面至少覆盖空、离线与深色。输入支持焦点、错误、键盘与大字体。

## 5. 设计验收

Figma 结构检查：组件复用、自动布局、文本不裁切、数据与单位一致、操作目标明确。

原型检查：食谱→详情→加入配餐→调整→保存→详情；设置→目标→返回；WebDAV→测试→同步→冲突处理；返回保留上下文。

Android 验收：真实背景玻璃、连续动画、可打断、减弱动态、键盘安全区、三键/手势导航、深色与大字体。静态截图不作为真实折射或同步成功的证据。
