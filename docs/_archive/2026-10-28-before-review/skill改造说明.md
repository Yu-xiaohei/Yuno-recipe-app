# recipe-nutrition 技能改造说明

> 致：编写/维护 `recipe-nutrition` 技能的 AI  
> 目的：生成餐谱 JSON 时，为每个食材写入营养权重 `healthWeight`，供「于の食谱」App 做目标热量/重量自动调配。  
> **本文只规定「怎么写字段、怎么判断、写到哪里」。具体权重数值由你根据该餐谱的营养构成自行判断，不设统一默认表。**

---

## 1. 要写入的字段

### 1.1 食材级（`items[]` 每一项，必填）

```jsonc
{
  "name": "芹菜",
  "weight": 190,
  "healthWeight": 0.92,   // 必填，0.01 ~ 1.00，两位小数
  "locked": false,        // 可选，true 时 App 调配不缩放该食材
  "energy": 26.6,
  /* 其余营养字段不变 */
}
```

| 字段 | 类型 | 范围 | 含义 |
|---|---|---|---|
| `healthWeight` | number | **0.01 – 1.00**，两位小数 | 营养权重：**越高表示该食材在这道菜里越应该被保留/优先** |
| `locked` | boolean | 可省略（默认 false） | `true` 时 App 在调配目标热量/重量时**不缩放**该项克数 |

### 1.2 顶层

```jsonc
{
  "schemaVersion": 2,   // 含 healthWeight 的文件用 2
  /* 其余字段不变 */
}
```

**禁止**：留空、超出 0.01–1.00、超过两位小数、只给部分食材写权重。

---

## 2. 语义（判断时以此为准）

| 权重含义 | 调总量时 App 的行为 |
|---|---|
| **数值越高 = 越健康 / 越应该保护** | 加热量时优先给它加；减热量时尽量少砍它 |
| 数值越低 = 越应该压缩 | 加热量时少给它加；减热量时优先砍它 |

`locked: true` 用于：改克数没有意义或会破坏菜式逻辑的项（典型：精盐、白糖、味精、某些固定调味）。锁定后权重仍要写，只是 App 不拿它做缩放。

---

## 3. 判断方法（由你按菜谱整体热量/营养结构自行裁定）

**不要套固定分类默认值。** 对每一道菜，按下列方法逐项判断：

1. **先看整餐结构**  
   看 `totals` 与 `macroRatio`（碳水/蛋白/脂肪供能比）、主要热量来源是什么（主食？油脂？肥肉？）、是否存在明显短板（蛋白偏低、脂肪偏高、钠偏高等）。

2. **再看单项在「这道菜」里的角色**  
   同一食材在不同菜里权重可以不同：
   - 在已经很油的菜里，烹调油的 `healthWeight` 应更低；
   - 在蛋白不足的菜里，瘦肉/蛋/鱼的 `healthWeight` 应更高；
   - 主食在「菜多饭少」的一餐里可以给中等权重，在「饭占大头」的一餐里应压低；
   - 蔬菜通常偏高，但若蔬菜是唯一亮点，可到接近 1.00。

3. **看做法与口径**  
   肥瘦、带皮/去皮、油炸/清蒸、生熟口径（按现有别名规则对齐后再判断）会影响权重。允许在判断后把理由写进 `notes`（一句话即可）。

4. **收敛到 0.01–1.00**  
   写出你认为合适的两位小数。同一餐内权重应能拉开差距（不要全写 0.5）；调味/油一般明显低于主料。

5. **`locked` 判断**  
   - 精盐、白糖、味精、味淋等微量调味：`locked: true`（同时 `healthWeight` 取很低，如 0.01–0.05）  
   - 油、酱油、酱料：一般 `locked: false`（减量时确实该少放）  
   - 用户明确说「油/盐不能少」的项：可 `locked: true`

## 4. 需要改动的文件

### 4.1 `SKILL.md`

在 **Step 4** 与 **Step 5** 之间增加固定步骤：

```markdown
### Step 4.5 — 为每个食材赋 healthWeight

对 items[] 每一项写入：
- `healthWeight`：0.01~1.00，两位小数，越高表示该食材在这道菜里越应保留/优先
- `locked`：不可缩放的调味写 true，其余默认 false 或省略

判断方法（不套固定默认表）：
1. 先看整餐 totals/macroRatio 与主要热量来源、营养短板
2. 再看该食材在「这一道菜」里的角色（主料/点缀/调味）
3. 做法与肥瘦/生熟口径影响取值
4. 同一餐内权重应拉开差距；理由可一句话写入 notes

顶层 `schemaVersion` 设为 `2`。
```

在「生成后体检」清单追加：

```markdown
- [ ] 每个 item 都有 healthWeight ∈ [0.01, 1.00]，两位小数
- [ ] 精盐/糖/味精等 locked:true
- [ ] schemaVersion = 2
- [ ] 权重在本餐内有区分度（不是全部相同）
```

### 4.2 `scripts/calc_nutrition.py`（推荐同步改）

1. 输出 JSON 时**校验** `healthWeight`：缺则报错；越界/三位小数则报错。
2. 支持从参数或中间结果带上权重，例如：
   `--health-weights "芹菜=0.92;熟米饭=0.58;精盐=0.01"`
3. `locked` 透传输出。
4. 顶层 `schemaVersion` 写 `2`。

> 脚本**不负责决定权重数值**，只负责校验、序列化、版本号。

### 4.3 可选 `references/aliases.json`

若某高频食材在你们的口径下权重长期稳定，可加 `healthWeights` 映射作**参考**；生成时仍允许按该菜谱微调，以你对本餐的判断为准。

```jsonc
{
  "schemaVersion": 2,
  "id": "chao-qin-cai-pei-xun-ji",
  "name": "炒芹菜配熏鸡",
  "items": [
    { "name": "芹菜",  "weight": 190, "healthWeight": 0.90, "locked": false },
    { "name": "熟米饭", "weight": 130, "healthWeight": 0.55, "locked": false },
    { "name": "猪肉",  "weight": 30,  "healthWeight": 0.40, "locked": false },
    { "name": "胡麻油", "weight": 3,   "healthWeight": 0.30, "locked": false },
    { "name": "精盐",  "weight": 1.5, "healthWeight": 0.01, "locked": true  },
    { "name": "酱油",  "weight": 8,   "healthWeight": 0.10, "locked": false }
  ]
}
```

（以上数字仅示意格式；**实际值由你按第 3 节判断**。）

## 6. 存量餐谱

旧文件（`schemaVersion: 1`、无 `healthWeight`）由 App 侧迁移脚本补写。  
技能只需保证**新生成**的餐谱带上完整字段。

---

## 7. 可直接转告的一句话

> 以后生成餐谱时，JSON 的每个 `items[]` 必须写入 `healthWeight`（0.01–1.00，两位小数）和可选 `locked`。`healthWeight` 表示该食材在这道菜里越健康/越应保留则越高；App 会按目标热量/重量调配克数。数值由你根据该餐谱的热量结构与营养构成自行判断，不要套固定默认表；精盐/糖/味精等用 `locked: true`。顶层 `schemaVersion` 设为 2。App 用户不能改权重。
