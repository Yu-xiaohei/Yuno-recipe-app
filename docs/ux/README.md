# UX 与 UI 开发交接

> 2026-10-28，规划文稿。作者自检与总负责人总检已完成（`B00-candidate-8`），等待用户按批次人工复核。文稿不代表 Android 已实现、Figma 已重绘或测试已执行。

## 阅读顺序

1. [流程与状态](流程与状态.md)：主导航、核心配餐、目标、导入/同步、公共更新与 APK 更新的可编辑 Mermaid 图。
2. [页面与组件契约](页面与组件契约.md)：页面输入、状态、副作用、Miuix 组合方式和跨页面约束。
3. [screen-contracts.json](screen-contracts.json)：稳定页面/状态/流程 ID、逻辑 route、动作守卫、数据边界和验收场景。

开发 Agent 先按任务定位 `Fxx` 流程，再读取相关 `Sxx/Mxx` 页面的输入与事件；不要仅按截图推断行为。组件角色是设计映射，不是已经存在的上游 API。

## 稳定标识

| 前缀 | 用途 | 示例 |
|---|---|---|
| F | 流程 | F03 加入与保存配餐 |
| S | 页面或独立操作表面 | S09 配餐编辑 |
| M | 通用模态 | M02 离开编辑保护 |
| ST | 页面局部状态 | ST-S09-saving |
| AC | 未执行的验收场景 | AC-S09-01 |
| D | 决定引用及未决技术边界 | D10 字体工程核验、D12 schema identity |

ID 是内部协作标识，不显示给 App 用户。保留 ID，不因文案修改重编号；删掉的 ID 不复用。`RETURN` 表示恢复来源上下文，`SYSTEM` 表示系统文档选择器或安装器；两者不是 App 页面。

## 边界

- 最新用户决定优先于旧稿；Figma 只作参考。全部 UI/动效服从项目 Miuix 基线，统一使用用户已确认的 MiSans 家族；工程仍需核验字体文件、许可、字重和缺字回退，禁止沿用设计中混杂字体作为规范。
- 当前既有名称可作为参考文案；新增用户可见名称由用户确认。图中用途说明、内部事件和逻辑路由不属于新产品命名。
- 用户已确认库内新增“食材”标签，与食谱共库，底部仍是配餐/食谱/设置。食材来自用户单独发布的每 100g JSON；本轮不新增 App 内手工营养录入。公共 Recipe 食谱来源从 100g 起步，但这不是配餐 UI 下限。
- 同日期与餐次仅一份配餐，继续添加编辑已有记录。重复条目按份数聚合、微调作用于总量；减份扣原始单份，0–9g 保留红框无效状态，可用滑块修正，保存时定位并阻止提交，调整到至少 10g 后才满足重量有效条件；首版不提供直接输入。固定范围以原始单份×当前份数为锚点，份数改变后按剩余份数计算，不把实际总量作为新锚点；identity 与独立食材原始份量来源在 P0 契约设计时复核。
- JSON 中 `Dxx` 是防止 Agent 猜测的阻塞标签；默认逐项问用户，用户要求时可一次合并多个问题；本目录不作为给用户阅读的待答长问卷。
- `S28` 复制/移动已确认为首版不提供，仅作后续版本候选能力，不占用首版批次。
- WebDAV 授权、OSS 地址和真机详情到相应环节再索取。开发 0% 时公共入口 404 正常，不据此判断实现缺陷。
- 本轮不修改原始 JSON/Markdown、源接口或 Figma；公共资源与私人配餐始终分开。

## 复核闸门

每个可审阅批次必须按“子 Agent 自检 → 总负责人交叉/集成总检 → 用户人工通过”推进。自检或总检失败退回原批次修正，复测后再交用户。用户未通过时，不启动依赖该批次的下游实现；独立的无依赖规划可以继续。

自检覆盖文件可读性、ID 和链接、图与机器契约一致、正常/失败/取消路径、副作用、缺失数据与快照。总检还要核对现有契约和并行任务是否冲突。人工复核材料应给可见流程与少量关键决定，不要求用户阅读整个 JSON。任何一层未完成都不能标注“已验收”。
