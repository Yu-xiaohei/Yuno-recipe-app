快照保存该记录当前已应用的来源口径；Recipe新版成功应用后整体替换该快照及派生营养，目标和餐次快照保留。缺营养为未知，不能视为0。配方内`locked`食材按当前已应用版本的原始基准固定；每次从该基准计算，避免反复舍入漂移。首版配餐只提供固定重量滑块并保存mode=weight；重量求解可继续，未知营养标为不完整。接口中的energy是后续纯计算能力，当前没有热量求解UI入口。不可达结果不称为精确达标。0≤重量<1g 保留为无效状态并显示红框，可通过滑块修正；点击保存时定位到无效条目并阻止提交，调整到至少 1g 后才满足重量有效条件，不能仅因存在另一条有效条目就绕过校验。移除是独立操作。

同日期+餐次只保存一份配餐，继续添加编辑已有。配餐重复加入同一独立库记录时合并一条显示 `x2` 等份数，保留原始单份和 source count，展示聚合总重量和热量；微调 `+100g` 只给聚合总量加 100g。已确认 `300g×2=600g → 固定滑块500~700g → +100g=700g → 删除一份扣原始300g → 剩400g×1`，然后重算营养；不按平均350g扣减，也不将微调后的结果乘份数。滑块相对原始单份×当前份数仅±100g，不重复累加；份数变化后仍按剩余份数对应的原始叠加量计算固定范围，不以实际总量重锚。0≤重量<1g 属于可保留、可用滑块修正的红框无效状态，所有条目至少1g后才满足保存重量条件。删除导致负值例外强制归零，不能自动移除或改成1g；最后一份再删才移除。D04主体已确认；首版不提供直接输入。独立食材默认加入100g已由用户确认，与其每100g营养口径分别记录；库记录以(originNamespace,libraryEntryId)独立识别；必须核验SHA-256，不能按名称、正文ID或hash合并库记录。只有重复加入同一库记录才在配餐聚合xN；独立记录即使hash相同也分别显示、分别加入。公共Recipe/Ingredient更新核验通过后，自动替换该库记录及已保存/正在编辑配餐中的对应配方并重新计算营养，无需逐份确认，不保留可浏览旧版；更新失败保留上一致状态并重试。D13已确认更新后保留当前已接受的实际总重，以新版配方重算；D14已确认越界自动调整至新版有效上下限并重算；技术失败保留上一致状态。

公共 Recipe 来源以 100g 起步；独立食材由用户单独编写每 100g 详细信息 JSON，与食谱共库发布。App 选取定义与重量后生成快照；无 App 内手工营养录入，不从食谱猜测食材营养。来源基准、Ingredient 每100g口径和配餐最低有效重量1g分别处理。具体 Ingredient schema 在 P0 设计，本轮不要求用户提前提供文件。

### 编辑状态与退出保护

```mermaid
stateDiagram-v2
    [*] --> clean
    clean --> dirty: 输入或添加/移除条目
    dirty --> calculating: 调配预览
    calculating --> dirty: exact/approximate应用或取消
    calculating --> invalid: 无法执行的输入
    dirty --> invalid: 重量0≤重量<1g或字段校验未通过
    invalid --> dirty: 全部条目至少1g且其他校验通过
    invalid --> invalid: 点击保存，定位红框并阻止提交
    dirty --> saving: 全部条目至少1g且字段有效，保存
    saving --> saved: 本地事务成功
    saving --> save_failed: 写入失败且回滚
    save_failed --> dirty: 保留草稿重试
    dirty --> exit_guard: 任何离开编辑意图
    exit_guard --> dirty: 继续编辑
    exit_guard --> saving: 保存后离开，全部条目至少1g且字段有效
    exit_guard --> invalid: 存在无效条目，回编辑定位红框并阻止离开
    exit_guard --> discarded: 明确放弃草稿
    saved --> [*]
    discarded --> [*]
```

状态对应 S09 的局部状态与 M02 退出弹窗；`exit_guard`、`discarded` 是图内控制节点，不是数据库状态。顶部返回、系统返回及跨 Tab 离开使用相同的草稿保护。仅本地保存成功后才完成“保存后离开”，同步失败不回滚本地成功。

## F04 历史、删除及候选转移

历史详情读取当前已应用Recipe版本的食材与重算营养，目标和餐次名称仍用保存时快照。公共Recipe更新自动替换已保存配餐及活动草稿，无需逐份确认；失败保留上一致结果并安排重试；D13已确认保留已接受实际总重，D14上下限自动调整已确认。锁定记录仍可导出和同步。

```mermaid
flowchart LR
    S06["S06 日期配餐"] --> S13["S13 历史快照"]
    S13 -->|删除| M01["M01 明确范围并确认"]
    M01 -->|取消| S13
    M01 -->|确认| Tombstone["事务写删除标记，待同步"]
    S13 -. "后续版本候选，首版不提供" .-> S28["S28 复制/移动候选预览"]
    S28 -. "后续版本再评估" .-> Decision["复制/移动不进入 v1"]
```

虚线仅表示后续版本候选；首版不实施复制/移动，不占用首版承诺或阻塞查看、锁定和删除闭环。

## F06 导入、预览、回滚与导出

```mermaid
flowchart TD
    S17["S17 设置"] --> File["系统文件选择"]
    File -->|取消| S17
    File --> Kind{"识别kind及入口能力"}
    Kind -->|mealBackup| S21["S21 只读校验"]
    Kind -->|libraryImport且开发者模式| S21
    Kind -->|普通模式库导入或未知类型| Invalid["拒绝；不写数据"]
    S21 --> Valid{"格式/版本/限制支持？"}
    Valid -->|否| Invalid
    Valid -->|是| Preview["数量/日期/重复ID/冲突预览"]
    Preview -->|取消| S17
    Preview -->|有效记录>0，用户确认且能力仍有效| Commit{"事务提交有效记录"}
    Preview -->|无有效记录| Invalid
    Commit -->|成功| Success["成功，按范围刷新"]
    Commit -->|任一提交失败| Rollback["回滚，原始数据保留"]
    S17 --> S22["S22 按所选范围生成导出JSON"]
    S22 --> Destination["系统文档写出"]
    Destination -->|实际写出成功| Exported["导出完成"]
    Destination -->|取消/失败| NotExported["不报告导出成功；源数据不变"]
```

导入先预览，无效记录按原因列出；确认后只导入有效记录。例如10条中2条错误时导入8条，错误2条不写入；有效记录为0时禁止提交。导出排除凭据、密钥和日志；文件选择不要求默认全部存储权限。

普通用户首版仅配餐备份导入导出；食谱/食材库导入仅开发者模式测试，深链、文件分派和提交均检查能力，导入后暂不可删除。配餐快照不自动建成库记录。来源更新包含直接引用Ingredient的线性重算；越界自动调整至新版有效上下限，用户编辑的无效草稿仍保留。公共库显式下架保留配餐/草稿条目及下架证据，打开对应日期详情时顶部横幅提醒，离线/重启不丢提醒。

## F10/F11 通用显示、清理和诊断

S25 主题与减弱动画影响显示，不改变营养或保存结果。清图片缓存不能删除配餐。清全部本地数据分类处理：配餐按选项 2 同步删除远端副本；食谱仅清本地缓存并按云端重新同步，只有云端删除才同步移除食谱；两者均显示同步结果。S26 默认隐藏，版本号连续点击 10 次后才出现；诊断只读、脱敏。

所有流程都覆盖亮/暗、大字体、键盘、三键/手势导航、动画减弱。API 31/32 走清晰简化表面，API 33+ 增强材质需工程验证；业务状态和数据完全一致。任何新用户可见名称、提示文案先交用户确认，不从内部图标签直接生成最终字符串资源。
