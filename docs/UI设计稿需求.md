# 「于の食谱」UI 设计交接 v3

> 2026-10-28。全部 UI 与动效遵循用户指定的 [Miuix jsCanvas](https://compose-miuix-ui.github.io/miuix-jsCanvas/)与 [Miuix 仓库](https://github.com/compose-miuix-ui/miuix)。现有 Figma 为待对齐的业务设计稿；产品规则见《完整方案 v3》和《UX v3》。未在 Figma 实现的要求不能据此标为已完成。

## 1. 基础规范

- 页面参考宽 430，采用自适应布局，不将参考像素机械等同所有 Android 设备的 dp。
- 全部基础控件优先映射 Miuix 对应组件，形状、字阶、间距、按压和弹簧行为以选定版本为准。品牌蓝 #3482FF 作为主题种子或主色映射，亮暗表面与文字使用 MiuixTheme 语义角色，不继续强制旧稿散落色值。品牌图标保留现有橙色。
- 保留碗叶占位。卡片、搜索、筛选、导航、设置行、菜单、对话框和底部弹层逐项对齐 Miuix；没有对应业务组件时组合已有控件。玻璃用于其示例支持的相应表面，不把“全部 UI 遵循 Miuix”解释为“所有卡片都必须折射”。
- 字体、字阶、颜色和间距记录与 Miuix 的对应关系。现有字体可作为字体家族配置，不能据此覆盖 Miuix 的整体排版层级。辅助信息不得仅靠低透明度区分。
- 状态色表示判断结果，不固定代表蛋白/脂肪/碳水。同时提供文字或图标。
- 图片 16:9 详情、方形卡片缩略；缺失时统一占位。

## 2. 页面与关键状态

| 页面 | 关键内容 | 必须补齐的状态/行为 |
|---|---|---|
| 启动 | 品牌、进度 | 本地读取成功（包括空库）直接进入默认食谱空态；读取失败才显示错误与重试，并保留全局导航 |
| 食谱首页 | 图片、名称、热量、重量、2–3 标签 | 默认/有旧数据同步/首次加载/离线/筛选空 |
| 搜索 | 输入、关闭、最近搜索、结果 | 至少2字符、空输入、组合输入、不足、无结果、清除确认 |
| 筛选菜单 | 重量/热量/分类多选 | 全部、已选、清空；同类 OR、跨类 AND |
| 食谱详情 | 图、范围提示、营养、食材、来源 | 不含主食提示、无图、营养缺失、展开、来源链接 |
| 今日配餐 | 全天合计、餐次卡、营养入口 | 有餐/无餐、未设目标、自定义餐数 |
| 日历与日期详情 | 选择日期、查询、当日餐次 | 无餐也可点、今日、选中、有餐、跨月 |
| 配餐详情 | 组合食谱、食材快照、更多 | 历史快照、锁定/解锁、同步状态、删除确认 |
| 新建/编辑配餐 | 日期餐次只读、实际/目标/状态、食谱调整 | 空、已改、不可达、锁定、保存失败、待同步 |
| 添加食谱/食材 | 两类选择、搜索、多选、重量口径 | 已选数、缺营养、自定义食材、返回保留草稿 |
| 营养目标 | 日/单餐、分配比例、目标类型 | 未设置、手动覆盖、差额、区间无效、餐次停用 |
| 设置 | 食谱数据、目标、备份、通用、关于 | 数据源分别表示食谱和应用更新源 |
| WebDAV | 配置、测试、频率、状态 | 未配置、测试中、失败、离线队列、冲突处理 |
| 导入导出 | 文件选择、预览、重复项、确认 | 无效/不兼容/取消/成功/部分拒绝说明 |
| 开发者模式 | 源诊断、日志、校验 | 正式默认隐藏；10次点击版本号解锁；脱敏 |
| 应用更新 | 版本、说明、下载、安装入口 | 稍后、取消、失败、校验失败、安装器返回 |

## 3. 重点修改

### 配餐编辑

显示清晰列头“实际 / 目标 / 状态”，以同一份样例数据联动各区域。条目重量、热量与顶部合计必须一致；不能把静态占位数字当成计算结果。

每道食谱使用相对原始单份×当前份数的固定 ±100g 滑块，首版不提供直接输入。0≤重量<1g 保留红框无效状态，允许用滑块修正；保存时定位并阻止提交，调整到至少 1g 后才满足重量有效条件。公共 Recipe 来源从 100g 起步，不作为配餐 UI 下限。旁边标明“按调配优先级调整食材”；可展开看原克数→新克数。锁定食材标识“不参与调整”。不可达目标显示可达范围与实际值。

“允许编辑”改为“锁定配餐”，说明“锁定后可解锁再编辑”。“同步至云端”在未配置时给配置入口。底部保存按钮保持可见，避开键盘和手势区；长页面使用固定操作区，不依赖滚到末尾寻找。

### 营养目标

“营养配比/总目标比例”改为“餐次分配比例”，防止与三大营养供能比混淆。指标编辑器包含目标类型：指定值、目标区间、仅上限。未设目标显示“未设置”。

膳食纤维统一 g；钠、维生素 C 为 mg；维生素列明确为维生素 C。公共发布稿的目标样例标为示例，不提供假定适合所有用户的默认数值。

### 食谱详情

标题与内容范围一致，例如已去面条的食谱显示“西红柿鸡蛋面卤”，提示不含面条。温馨提示使用当前营养数据，不复用旧菜或旧版本数字。

食材默认按行展开，完整表格为可选详细视图。无需为了展示全部字段把九列表格缩到手机屏宽。来源、生成信息、许可放在次级区块。

### 同步与恢复

移除无提示“最新覆盖旧文件”的语义。冲突页同时显示设备、修改时间和内容差异，提供保留本机、保留远端、两份都保留；处理前双方数据均在。

清缓存与清本地数据明确分开。清数据确认页列出配餐、导入食谱及同步状态，支持先导出；正文不展示密码和 token。

## 4. 组件维护

当前组件库已有按钮、搜索/输入、筛选、导航、食谱/餐次卡、设置行、日历、弹窗、菜单及业务模块。先建立“现有组件 → Miuix 组件/示例与版本”的映射，再更新母组件及实例；现有组件的复用不能阻止对齐 Miuix。未经核验的尺寸与动效标注为待对齐，不写成上游标准。

新增重点：目标类型编辑器、实际/目标/状态行、调配不可达提示、锁定状态、同步状态、冲突对比、导入预览。命名保持简洁；可见文案不塞实现细节。

每个可操作组件至少覆盖默认、按压、禁用、加载、错误；页面至少覆盖空、离线与深色。输入支持焦点、错误、键盘与大字体。

## 5. 设计验收

Figma 结构检查：组件复用、自动布局、文本不裁切、数据与单位一致、操作目标明确。

原型检查：食谱→详情→加入配餐→调整→保存→详情；设置→目标→返回；WebDAV→测试→同步→冲突处理；返回保留上下文。

Android 验收：API 33+ 的真实背景玻璃，以及 Android 12/12L 的清晰简化材质；两者均检查连续动画、可打断、减弱动态、键盘安全区、三键/手势导航、深色与大字体。静态截图不作为真实折射或同步成功的证据。优先单 APK，具体兼容门槛见《Android兼容与验证方案.md》。

> 2026-10-30统一基线：库记录以(originNamespace,libraryEntryId)独立识别；必须核验SHA-256，不能按名称、正文ID或hash合并库记录。只有重复加入同一库记录才在配餐聚合xN；独立记录即使hash相同也分别显示、分别加入。公共Recipe/Ingredient更新核验通过后，自动替换该库记录及已保存/正在编辑配餐中的对应配方并重新计算营养，无需逐份确认，不保留可浏览旧版；更新失败保留上一致状态并重试。D13已确认更新后保留当前已接受的实际总重，以新版配方重算；D14已确认越界自动调整至新版有效上下限并重算；技术失败保留上一致状态。最低有效配餐条目总重1g，0≤重量<1g保留红框草稿并阻止保存；100g来源/营养口径及±100g滑块不变。

## 2026-10-30 补充基线

来源更新越界自动调整至新版有效上下限；独立食材按每100g线性重算。公共库显式下架后保留私人配餐/草稿最后数据，S13顶部横幅提醒，文案固定为“部分食谱已删除，已保留原有数据”（D19已确认）。S17正式导入仅配餐备份，库导入仅S26开发者测试且暂不可删，所有入口和提交门控。餐次沿用Figma两/三/四/五餐比例预设及自定义，默认三餐2:4:4；节点和数值见[目标契约](contracts/goal-transfer-policy.md)。
