# 「于の食谱」UX 交互规则 v3

> 2026-10-28。根据原口述稿、现有 Figma 及本次用户回答整理。原口述稿完整保存在 `_archive/2026-10-28-before-review/于の食谱 UX.md`。

## 1. 全局导航与返回

三个 Tab 为配餐、食谱、设置，启动默认食谱。每个 Tab 保留自己的滚动位置与筛选。搜索、详情、新建和设置子页有明确返回入口。离开有改动的配餐编辑页时，提供继续编辑、保存和放弃选项。

全局 UI 与动效以 Miuix jsCanvas 示例及仓库为准。页面转场采用 miuix-nav 的 Miuix 预设，模态和控件交互沿用相应组件行为；不将旧稿自定义的逐项果冻入场设为强制流程。搜索和滑块手势优先，不与切页手势争抢。浮动导航与透镜材质的适配规则见《Miuix-UI与液态玻璃基线.md》，不把 iOS-like 示例直接当成 HyperOS 4 默认风格。

## 2. 食谱首页与搜索

首页展示食谱卡片：图片或碗叶占位、名称、热量、重量和 2–3 个分类标签。默认按发布时间倒序。搜索框进入独立搜索页。筛选维度为重量、热量、分类；按 Figma 已确认的弹出菜单选项展示，同维度 OR、跨维度 AND。

搜索至少 2 个有效字符；不足时显示“请输入至少两个字或字符”。支持名称、食材、中文跨字、全拼及简拼，按相关度排序。输入空白不入历史；只将用户提交的有效查询加入历史，不记录每个输入中间态。

历史去重并按最近使用排序，应用不设条数上限，界面最多展示 5 行；超出显示窗口的历史由设备策略清理。清除全部须确认。关闭搜索回到原列表位置。无结果显示查询词和清除筛选入口。

## 3. 食谱详情

缩略图过渡到 16:9 顶图。无图仍使用同一家族占位。显示配方包含范围，特别标明“不含主食”；温馨提示必须来自当前配方，不能保留上一版本的热量或重量。

总览包含重量、热量、碳水、蛋白、脂肪、维生素 C、膳食纤维、钠。膳食纤维用 g，维生素 C 和钠用 mg。手机食材列表默认只显示名称、克数和热量，展开后展示其他营养、每 100g 数据和来源；避免把九列数据压在手机屏宽内。

查看食谱本身不改变配方。“加入配餐”先选择日期和餐次，再进入编排。返回不丢失配餐草稿。

## 4. 今日配餐与日历

配餐 Tab 展示今天各餐次快照合计。顶部热量与重量为所有已保存餐次的真实合计，蛋白/脂肪/碳水按目标判定动态变色，颜色不固定绑定某种营养。

自定义餐次按用户模板排序。未添加的餐次显示空状态并可新建；已有餐次进入详情。查看全天营养时可切换单餐。没有目标的指标显示“未设置”，不做红绿判断。

日历有餐和无餐日期均可选择；有餐日期加标识，今天、选中、无餐状态可叠加。点查询进入所选日期；无餐日期仍展示空餐次并支持新增。日期与星期由同一日期值计算。

## 5. 新建与编辑配餐

日期与餐次在当前编辑页只读。首版不提供复制/移动配餐；后续版本可复制配餐配置并独立处理日期与餐次。

选择食谱或独立食材后显示营养合计；独立食材需提供与重量状态匹配的每 100g 数据，缺失项显示未知。重复加入同一独立库记录才合并显示 xN；两条库记录即使hash相同也分别加入。重量与营养展示聚合总量，微调不再乘份数；删除一次扣原始单份，最后一份再删除时才移除条目。

每道食谱以原始快照为基准，仅提供相对原始单份×当前份数的固定 ±100g 滑块，首版不提供直接输入，反复拖动不累加范围。始终按 healthWeight 重新分配食材；预览新总重、热量及主要食材变化。locked 项保持克数；超出可达范围显示实际可达值，不能悄悄假装命中目标。删除扣减为负数时强制归零；0≤重量<1g 保留红框无效状态，可通过滑块修正，保存时定位并阻止提交，调整到至少 1g 后才满足重量有效条件，不自动移除或改为 1g。公共 Recipe 来源从 100g 起步，与配餐最低有效重量分开处理。

营养表明确列头“实际 / 目标 / 状态”。目标区间和仅上限按接口判定；编辑过程中直接联动，不用演示占位值充当合计。保存前必须验证合计与条目一致。

“锁定配餐”默认关闭，开启后保存为只读；详情提供主动解锁。“同步至云端”仅在已启用且配置 WebDAV 后可开；未配置时提供配置入口。同步失败仍保留已保存的本地配餐并提示待重试。

## 6. 历史配餐与删除

详情展示当前已应用版本的配方与重算食材/营养，不提供旧Recipe版本选择；公共新版核验后自动维护并刷新已保存配餐和活动草稿。目标与餐次使用保存时快照；公共Recipe/Ingredient更新核验通过后，自动替换该库记录及已保存/正在编辑配餐中的对应配方并重新计算营养，无需逐份确认，不保留可浏览旧版；更新失败保留上一致状态并重试。D13已确认更新后保留当前已接受的实际总重，以新版配方重算；D14已确认越界自动调整至新版有效上下限并重算；技术失败保留上一致状态。

更多菜单提供编辑、锁定/解锁、导出、同步状态和删除；首版不提供复制/移动。删除须确认，并生成同步删除标记；冲突副本不会自动覆盖主记录。

## 7. 设置

| 分组 | 内容 |
|---|---|
| 食谱数据 | 食谱库版本、更新时间、公共源、更新频率、手动更新及部分失败明细 |
| 营养目标 | 餐次名称/数量/顺序、分配比例、日目标、单餐目标、区间/上限类型 |
| 备份与恢复 | 配餐导入导出、食谱导入、WebDAV |

导入预览中按条显示无效记录与原因；确认后只写入有效记录，10 条中 2 条错误时导入 8 条，错误记录不写入；有效记录为 0 时禁止提交。
| 通用 | 主题、省流、减弱动画、清理图片缓存 |
| 关于 | 应用版本、应用更新源、检查更新、更新日志、开源与许可 |

目标页先设置日目标，再按餐次比例分配；允许单餐覆盖。比例是餐次分配比例，不是三大营养供能比。更改模板不改变历史餐单；删除有历史记录的餐次只停用模板，保留历史名称与 ID。

WebDAV 页提供启用、服务器、账号凭据、测试连接、同步频率、手动同步和状态。冲突默认保留双方版本；页面不提供无提示覆盖所有旧文件的开关。测试成功后才能显示服务器可用。

开发者模式通过连续点击版本号 10 次解锁，正式默认隐藏。功能包括脱敏日志、源诊断及数据校验。清除缓存不能删除配餐；清全部本地数据分类处理：配餐按选项 2 同步删除远端副本，食谱只能云端删除并同步移除；清食谱本地后按云端重新同步。首版不展示“AI 营养规划”入口。

## 8. 通用状态

每个输入/提交流程覆盖默认、禁用、加载、错误和成功。首次加载可用骨架；已有数据后台刷新时保留内容。错误提示给出可执行恢复入口。深色、字体放大、键盘、安全区、三键导航、减弱动画均需验收。

库记录以(originNamespace,libraryEntryId)独立识别；必须核验SHA-256，不能按名称、正文ID或hash合并库记录。只有重复加入同一库记录才在配餐聚合xN；独立记录即使hash相同也分别显示、分别加入。

## 2026-10-30 集中答复同步

Recipe更新保实际重量，越界自动落到新版有效上下边界；独立Ingredient也自动更新配餐/草稿，按per100重算。公共库下架保留最后条目数据，详情顶部横幅提醒，证据随备份/同步保留。食谱/食材本地导入仅开发者模式，导入后暂不能删除；配餐备份入口保留，快照不建库。餐次比例使用已核对Figma预设及自定义，三餐当前2:4:4；详见[目标契约](contracts/goal-transfer-policy.md)。
