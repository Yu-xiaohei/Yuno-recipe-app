# 私人配餐同步与冲突契约

候选：`B01-candidate-7`；任务：`P0-04`；关联 `F07/F11`、`S18/S19/S20/S25`。本文为实现边界，不表示123云盘账号、WebDAV读写、ETag或双端同步已验证。

## 数据与协议边界

私人同步仅使用用户主动配置的123云盘 WebDAV 专用目录。OSS 是公共 Recipe/Ingredient 和图片的只读来源，不存私人配餐。停用同步不删除远端，也不清掉未处理的本地操作。

[sync.schema.json](../../schemas/sync.schema.json) 定义 `schemaVersion=1`、`kind=syncEnvelope`、payload。payload 完整引用 [meal.schema.json](../../schemas/meal.schema.json)，可为有效正式配餐或其 tombstone；保存当时目标的 goalSnapshot 随配餐同行。首版不额外同步当前全局 GoalProfile、餐次设置或公共目录，避免扩大已确认数据流。

revision、parentRevision、deviceId 和日期/餐次身份由 payload 持有；envelope 不再复制一套可能矛盾的同名值。每次变更生成新 revision，设备时间仅用于显示。传输内容的字节 SHA-256、服务器 ETag 与共同基线位于本地/传输元数据，不能将自带 contentHash 放进被 hash 的同一文件。SHA-256保证字节一致性，不是服务身份认证或密码。

## 本地成功与原子队列

本地保存、锁定/解锁、删除或导入的正式事务同时生成 outbox 操作；事务失败时两者都回滚。UI先呈现本地保存结果，联网失败不回滚已保存的配餐。outbox绑定精确 recordId、revision、字节载荷或其不可变引用、预期共同基线、服务端点/账户范围和幂等操作ID。发送或重试不能从变化中的“当前记录”临时拼装另一份载荷。

同步元信息记录 `lastSyncedRevision`、源字节 hash、强ETag、已探测能力、远端命名空间及待确认操作。pending/syncing/synced/failed/conflict/disabled/backup_only 是同步状态，不替代“本地已保存”。收到写入成功后更新基线与完成标记，回读并验证实际 revision/hash；不把发送进度到100%称为同步成功。

连接配置与凭据仅保留本地安全引用；导出和远端 payload 都不能包含密码、token、AccessKey、credentialHandle、端点设置或网络日志。切换账户/目录时原队列保留原作用范围，不能把旧账户的删除操作发送到新账户。端点和路径必须验证，认证信息不得跟随跨源重定向；不能关闭证书验证绕过错误。

## Recipe自动更新的同步边界

公共Recipe自动维护已保存配餐时同样生成新record revision及不可变outbox，并通过已配置的私人WebDAV同步；不上传到公共OSS。旧待发载荷不能就地换成新版，按同记录操作顺序及预期基线处理，失败不丢队列。活动草稿的自动维护只改草稿，不直接外传未保存内容。

两端同时更新、源更新与私人编辑竞争、或接收远端旧源快照，仍执行完整候选及共同基线比较；不能以公共版本较新就覆盖另一端私人改动，也不能因自动更新而删除未解决冲突副本。收到旧源版本的合法配餐，先按同步协议接收一致记录，再按本地可用且已核验的公共Recipe版本安排维护；离线无新版时不声称已更新。目标和餐次快照随原记录保留。

## 条件写入与比较

实际接入阶段只在获准专用测试目录探测读取、创建、修改、删除、强ETag与条件写入。一次GET成功不代表PUT、删除或并发保护可用。

| 当前比较结果 | 行为 |
|---|---|
| 本地和远端均等于共同基线 | 无内容写入；核对一致后更新状态 |
| 仅本地变化，远端等于基线 | 使用可靠强ETag的 If-Match 条件提交完整候选 |
| 仅远端变化，本地等于基线 | 校验结构/语义/身份后事务应用远端并更新基线；接收旧Recipe/Ingredient源版本时保留一致载荷并排入已确认的自动引用更新流程 |
| 同 recordId 的双方都改变基线 | 建立冲突，保留双方载荷与基线，不按时间胜负 |
| 新记录在已验证的远端路径确实不存在 | 使用 If-None-Match:* 条件创建；并发创建冲突后重新读取比较 |
| 读取、鉴权、列举或连接失败 | 保留本地与待同步状态；失败不是“不存在”，不条件外覆盖 |
| 写入超时，结果未知 | 回读匹配操作/revision/hash；相同视为已完成，不同则重新比较，读失败继续待定 |
| 条件不满足或解决时远端再次变化 | 重新读取并建立/更新冲突；禁止沿用旧选择盲写 |

HTTP If-Match 使用强比较；弱ETag、忽略条件的服务器、只能给时间戳或不能稳定回读的服务均不能当作可靠并发保护。能力不满足时停用无人值守双向覆盖，降为已确认的显式备份/恢复；恢复仍先预览与冲突选择，不能以降级为由覆盖双方。

## 冲突副本与日期唯一性

冲突记录独立保存 `conflictId`、原因、相关recordId、基线、双方完整候选、源revision/hash/ETag和当前选择。冲突副本不插入日历主表，主表继续满足“同日期+稳定餐次ID仅一份有效配餐”。

即使 recordId 不同，两台设备各自新建同日期同餐次也会撞唯一键，必须进入日期/餐次冲突流程；“不同ID独立合并”不能绕过此约束。两份保留表示在冲突存储中保留另一候选，不能默认为同一餐次显示两份正式配餐，也不暗中实施首版未提供的复制/移动。

用户可选本机、远端或双方保留；选择只改变暂存意图。取消保留双方，记录仍显示冲突。确认后用最新基线生成新revision并条件提交，成功后才将对应冲突标为已处理；解决失败、远端再变或本地事务失败时保留副本。数量、原始基准、当前总量、目标、锁定与算法版本作为完整候选处理，不逐字段盲合并。

## 删除、清除与防复活

删除私人配餐写 tombstone 与outbox，不直接忘掉远端身份。清除配餐本地数据按用户已选方案同步删除云端，仍需保留最小恢复元信息、待删ID和队列直到远端结果确认；不能先清空队列、共同基线和凭据引用再报告完成。断网时显示删除待同步，不把它冒充云端删除成功。

清除全部配餐不能只枚举本机已知ID就声称清掉云端。执行前必须可靠列举并读取远端集合，校验其范围和版本，与本地集合合并为明确的删除清单；按项目双次确认展示本地/远端范围后，先持久化每项tombstone及outbox，再逐项条件写入、回读确认。离线或远端分页/列举失败时，未知远端集合保持待处理，不能显示“云端全部已清除”。列举和执行之间新增的记录也不能被无保护删除；重新列举发现范围变化时重新预览/确认，不以旧清单自动扩大删除范围。

远端 tombstone 与本地未同步编辑相遇时建立删除/编辑冲突，不能静默复活或丢弃未同步编辑。已确认删除标记参与后续同步；首版没有经过验证的跨设备确认/回收协议前不自动GC tombstone。离线旧设备回来时必须比较删除记录与共同基线，不把云端路径缺失当作可直接重新上传的理由。

命名空间重置、队列清理和清除元信息不能掩盖待确认删除；若需要 reset/epoch 机制，先确认旧范围已完成或显式保留隔离待处理状态，再建立新命名空间。不得通过本地 reset 跳过用户的云端删除预期。远端数据实际删除、清同步数据等重大操作遵守项目双次确认；本契约本身不提供执行授权。

公共食谱只有云端显式delete才从公共本地库移除；清本地食谱缓存后按云端重拉。清公共缓存不删私人配餐、历史来源快照或WebDAV待处理队列。

## 必须保留的后续验证

B11前需在两端及故障注入环境验证：单端修改、双端修改、同日期不同ID新建、锁定/解锁、微调/减份、删除/编辑冲突、超时后实际写成、弱ETag或假条件写、鉴权失败、取消解决、远端再变、离线清除与旧端防复活。当前没有执行任何真实服务操作，也不宣称Schema能证明协议可靠。

上述规范定义协议语义，不证明123云盘特定账号已经正确实现；实际能力探测仍是接入批次的准入条件。

公共Recipe及直接引用Ingredient维护均沿新revision/outbox同步；sourceAvailability下架证据随正式配餐及冲突副本传递，私人记录deletedAt仍为null。接收下架标记保留最后快照/重量/营养；草稿不因源维护自动上传。目录缺席或网络失败不能制造删除证据。
