# 模块写入与交接边界

候选：`B01-candidate-7`。当前只有契约与校验代码，以下模块目录是后续任务范围，不表示已经建立 Android 模块。

| 所有者 | 写入范围 | 共享入口与限制 |
|---|---|---|
| MAIN | 根规则、台账、契约整合、评审、总日志、导航/数据库注册 | 统一版本与迁移注册；集成前核对G1，人工接受后放行依赖 |
| DATA | 分配的 schemas、`core/model`、`core/calculation`、数据夹具 | 共享schema仅单所有者修改；不直接写UI或仓储实现 |
| PLATFORM | 根Gradle/Wrapper、`gradle`、Android基础、材质原型 | B01接受后开始B02；依赖版本和Manifest例外由MAIN整合 |
| UX/DESIGN | 分配的UX/UI契约、`core/design`、正式资产 | 新可见名称需用户确认；不改业务计算或导航注册 |
| CATALOG | 库浏览、搜索、筛选、详情 | 只调用RecipeRepository；不直接改公共源或历史快照 |
| MEAL | 配餐UI、草稿事件、日历 | 只调用MealRepository和纯计算端口；不能另写一套数量算法 |
| GOALS/TRANSFER/PUBLIC/SYNC | 分波分配的功能目录 | 不共写事务实现/迁移；端口变更先交MAIN |
| QA | 分配的 `tests/test_*`、独立报告 | 只读固定待审候选；不修改被审代码以使测试通过 |

并发最多总负责人加3名子Agent；同一文件同一时间只有一个写入者。子Agent对总日志、台账、共享版本和迁移的建议交MAIN处理。读者可以并行核对，写者在冻结待审候选时暂停该候选编辑；修订会使受影响hash和检查证据失效。

B01写入分工：公共数据四份schema和catalog-data由数据执行者提交；UI基线由UI执行者提交；数量/配餐/仓储、台账、索引、测试和总检由MAIN整合；目标/导入/同步由单独执行者提交。独立审查只读。所有文件最终以评审包hash清单为准。

B02/B03不能消费尚未人工接受的契约作为已冻结实现依据；其只读调研不构成集成。当前不创建隔离工作树、不提交或推送远端；Git重大操作按项目双次确认规则另行执行。
