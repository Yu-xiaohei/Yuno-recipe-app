## 复核方式

每个批次走“执行者自检 → 总负责人总检 → 用户人工复核”。用户已确认按可审阅批次复核。前置批次未得到用户明确接受，依赖它的实现不进入 `ready`；只读探索和不影响依赖的独立规划可以继续。

状态：`planned → ready → in_progress → self_check → integration_check → human_review → accepted`；退回为 `changes_requested`，外部条件缺失为 `blocked`，取消为 `cancelled`。检查结果另记 `pass/fail/not_run`。

## 任务颗粒度

完整的 85 个任务、唯一 ID、角色和依赖保存在 `config/project-plan.json`。按阶段概览如下：

### P0：契约、工具链与核心纯模块

- **B01（P0-01～P0-07）共享契约**：裁定调配聚合剩余边界；定义 Recipe、Ingredient、混合库索引、MealRecord 数量分组、目标/导入/同步协议；冻结 Repository 接口和 UI screen ID。未确认的用户文案和字体不能进入实现。
- **B02（P0-08～P0-13）工具链与材质**：初始化工程和 Wrapper，锁定 JDK/Gradle/AGP/Kotlin/Compose/Miuix；建立低版本简化材质及 API33 增强材质隔离；完成 API31/32/33 安装、冷启动和 vivo 真机候选证据。不能只用 `overrideLibrary` 代替兼容审计。
- **B03（P0-14～P0-21）数据与计算**：参考数据逐文件hash盘点、重复审计并保留独立记录、来源核实；公共 Recipe 以 100g 起步的来源基准与 Ingredient 每100g口径分开；schema/迁移预览；目标判定、营养计算、healthWeight 有界求解；数量聚合、固定 ±100g、至少1g有效重量、逐份删除和零值红框黄金向量；交接食谱生成技能并总检版本。

### P1：本地核心闭环

- **B04（P1-01～P1-06）本地底座**：日期+餐次唯一事务、草稿恢复、统一字体主题、三 Tab/返回、安全区和公开 Mock 契约。
- **B05（P1-07～P1-13）目录**：食谱与食材同库、标签、至少两字符搜索、IME、中文/拼音、筛选历史、详情展开和加入上下文。
- **B06（P1-14～P1-21）配餐**：日期日历、加入与 `xN` 聚合、固定锚点滑块、不可达/未知/0g、逐份删除、锁定解锁、历史快照和删除标记。
- **B07（P1-22～P1-25）集成**：真实仓储替换 Mock，断网浏览→搜索→添加→保存→杀进程重启，核对目标/餐次快照保留及Recipe自动更新后的重算一致性，并完成 API31/32/33 与 vivo 候选人工复核。

### P2：目标、传输、公共源和私人同步

- **B08（P2-01～P2-05）目标与餐次**：指定值/区间/上限、餐次比例、手动覆盖、停用/改名、历史目标快照。
- **B09（P2-06～P2-10）JSON**：正式用户仅配餐备份导入导出；食谱/食材libraryImport仅开发者测试且导入后暂不可删除，文件分派/深链/预览/提交均门控。系统文件选择、版本识别、预览、冲突、原子提交、往返和凭据排除保持；10条中2错误只导入8条，取消零写入，配餐内嵌快照不建库。
- **B10（P2-11～P2-15）公共数据/更新**：生成 OSS 公共食谱与图片索引，校验、缓存、回退、部分失败重试和 APK versionCode；地址到此阶段再索取。404 在未部署阶段是正常状态。
- **B11（P2-16～P2-22）123 WebDAV**：安全配置、读写/ETag/条件写探测、队列、本地优先、冲突副本、tombstone、降级备份和双端故障注入；不把 OSS 当 WebDAV。

### P3：发布候选和分发

- **B12（P3-01～P3-05）发布资料**：自适应/单色图标，隐私和第三方许可，签名/双包后备方案，设置诊断和清数据范围；用户确认名称、许可和签名方案。
- **B13（P3-06～P3-10）总回归**：复现构建、正式签名候选、功能/离线/升级/恢复/API/性能/无障碍回归，绑定同一候选证据。
- **B14（P3-11～P3-13）公开分发**：用户明确授权后才分发 GitHub/Gitee APK，核验下载/完整性/安装并交接回滚和恢复步骤。
