# 附录 A：Miuix 视觉与动效 v3

> 2026-10-28 基线更新。全 UI 依据用户指定的 [jsCanvas 示例](https://compose-miuix-ui.github.io/miuix-jsCanvas/)与 [Miuix 仓库](https://github.com/compose-miuix-ui/miuix)。具体源码、版本、支持范围与验收状态见《Miuix-UI与液态玻璃基线.md》。此前 v3 已备份到 `_archive/2026-10-28-before-miuix-baseline/`。

## A1. 全局设计体系

全部基础组件、字阶、表面、形状、间距与交互动效遵循选定版本的 Miuix；现有 Figma 按此对齐。食谱卡片、营养表和目标编辑器通过组合 Miuix 控件实现。品牌蓝 #3482FF 与碗叶占位作为应用配置/资产保留。

颜色使用 MiuixTheme 的语义角色，亮暗主题采用对应配色。连续圆角采用上游形状实现。旧稿写死的背景色、56/48dp 导航尺寸、240–380ms 转场及自行指定的弹簧值不再是硬性规范；以选定组件/示例及真实适配结果为准。

全部 UI 遵循 Miuix，不代表全部 UI 都加液态玻璃。正文、食材和设置行遵循其清晰的信息层级；悬浮栏、搜索、菜单等按对应示例使用材质。

## A2. 控件与页面动效

页面转场使用 miuix-nav 的 MiuixDefault；模态按页面角色使用 Modal，减弱动画使用可用的无动画/简化策略。返回手势、可打断与状态恢复遵循上游运行时，不将 AOSP 或 iOS-like 预设静默混为全局默认。

按钮、开关、滑块、菜单、对话框、弹层和滚动反馈沿用相应 Miuix 控件。旧稿“所有内容逐项果冻进出”不再是必选效果。业务状态变化可增加必要反馈，但不复制一个与基础库相冲突的动画体系。

搜索、滑块和列表滚动优先各自手势；预测返回或拖动关闭按所用组件配置，并单独验证草稿保护和手势竞争。同步成功、失败和冲突仍必须以可读状态表达。

## A3. 材质实现

API 33+ 的背景采样、模糊、混色与高光采用 miuix-blur，运行 Shader 使用 miuix-shader。Android 12/12L 按用户确认采用清晰的简化表面，保留 Miuix 动效；不调用该 Shader 效果路径。先使用上游能力，不默认引入第二套模糊库。只有明确存在能力缺口且已核实兼容性后，才记录必要扩展。

完整透镜、色散与液态导航可参考仓库 example 源码；其完整透镜导航入口名为 IosLiquidGlassNavigationBar，示例设置区分 Default 与 iOS-like。它是可适配的示例，不是已经接入食谱 App 的稳定公共组件，也不是小米系统私有材质的已验证复现。

Figma 的透明、模糊和高光只负责表达视觉意图；Android 真实滚动背景中的采样、折射、形变和光感需单独验证。玻璃包含模糊这一基础步骤，但仅前景透明或高斯模糊截图不足以验收所要求的液态效果。

## A4. 支持与版本

已核对 main 提交 bb7bde3109605b4c98065b53030ba429c39baea9，以及正式 Release v0.9.4 的说明。正式依赖、main 源码与网页部署不混为同一版本。实际依赖选择须先构建验证再固定。

当前完整 Shader 效果以 Android 13 / API 33 为能力门槛。正式 0.9.4 blur AAR 的 minSdk 为 33，所检查的 ui/shader/blur AAR 要求 minCompileSdk 37。优先单 APK 自动选材质，低版本安装范围、依赖 Manifest 合并与运行时隔离需分别通过验证，失败再拆包。详见《Android兼容与验证方案.md》。

## A5. 验证页与验收

先建立含真实滚动内容、浮动导航、搜索、菜单、底部弹层和滑块的 Miuix 验证页，再推广到所有业务页面。

- 明暗主题、复杂图片、大字体下可读；文字和图标不被折射扭曲到不可辨认。
- 背景采样随滚动正确更新，高光和阴影随轮廓，无矩形底板、透明黑边或采样错位。
- 导航等分、可打断、快速连续切换与返回符合上游行为；手势不抢滑块和输入。
- 系统状态栏、三键/手势导航、键盘和 Snackbar 安全区正确。
- 低版本/性能不足时使用清晰的简化表面，减弱动画后仍可理解所有状态。
- 每项分别记录源码依据、Figma 对齐、Android 接入和真机验收，不把任一项冒充全部完成。

当前只完成来源核验与设计基线更新；本项目液态玻璃尚未接入或真机验收。
